## 주요 수정사항

### 개요

한 반응의 [Contents]에 같은 내용 부호를 두 번 넣으면 그 부호가 두 번 집계되던 문제를 수정했습니다. 예를 들어 `Bt`를 두 칸에 반복해 넣으면 Isolation Index의 분자가 실제보다 커지고, 경계에 있는 기록에서는 CDI 판정까지 달라질 수 있었습니다. 이제 한 번 선택한 내용 부호는 같은 반응의 다른 칸에서 다시 선택할 수 없습니다. 과거 자동저장 자료에 중복 부호가 남아 있으면 원본을 임의로 바꾸지 않고 계산을 멈춘 뒤 확인할 행을 알려줍니다.

데스크톱 표와 모바일 카드가 서로 따로 갖고 있던 반응 정리 규칙도 한곳으로 모았습니다. `DV`, `DR`, `INCOM`, `FABCOM` 계열에서 Level 1과 Level 2가 함께 입력되면 화면에서 방금 고른 부호를 남기고, 이전의 충돌 부호를 제거합니다. 과거 저장 자료에 두 수준이 이미 함께 들어 있으면 기존 데스크톱 동작과 같이 Level 1을 남깁니다. 어느 수준이 맞는지는 원자료에 따라 임상가가 확인해야 하며, 제거된 자리에는 빈 특수점수가 저장되지 않습니다. 같은 규칙이 두 화면에서 같은 입력에 같은 결과를 냅니다.

이번 패치는 구조요약 계산 공식을 바꾸지 않습니다. 규칙에 맞게 입력된 기존 프로토콜은 다시 계산할 필요가 없습니다. 아래 ‘어떤 기록이 영향을 받나요?’에 적은 조건에 해당하는 자료만 원자료를 확인한 뒤 다시 계산합니다.

### 자동저장과 입력 자료

- 저장된 작업이 있는 상태에서 샘플 데이터를 열어 보아도 기존 자동저장본을 덮어쓰지 않습니다.
- 편집 직후 화면을 닫거나 다른 페이지로 이동해도 마지막 변경을 저장하도록 보완했습니다.
- 구조가 손상되었거나 지나치게 큰 자동저장 자료는 그대로 복원하지 않고 안전하게 거부합니다.
- 허용 목록에 없는 Z 부호와 카드에 맞지 않는 Z 점수는 계산 전에 차단합니다.
- CSV 파일명은 사용 중인 기기의 현지 날짜를 사용합니다. 내보낼 때는 스프레드시트가 수식으로 실행할 수 있는 문자열만 안전하게 처리하고, 임상적으로 유효한 음수·양수와 단독 채점 부호는 원래 값으로 유지합니다. 쉼표, 따옴표, CR·LF 줄바꿈이 있는 셀도 CSV 규칙에 맞게 인용합니다.

### S-CON과 참조 문서

다섯 언어 S-CON 참조 문서에 12개 기준과 `8개 이상`의 판정 경계를 모두 명시했습니다. 계산기 화면은 지금까지와 같이 12개 기준의 충족 개수를 계산하고 8개 이상이면 체크하며, 만 15세 이상의 수검자에게 적용한다는 안내를 함께 표시합니다. 나이 입력란은 추가하지 않았고, 적용 연령의 판단은 임상가에게 남겨 둡니다.

AI 해석 도우미는 나이가 제시되지 않은 S-CON 질문에서 먼저 기준 충족 개수를 설명하고 정확한 나이를 묻습니다. 나이를 모르는 상태에서 S-CON을 양성 또는 음성으로 확정하거나 보고서 문장으로 완성하지 않도록 답변 규칙을 보강했습니다.

### AI 세션과 피드백 보안

- API 키 세션 발급과 채팅 요청에 세션 회전만으로 우회하기 어려운 요청 제한을 추가했습니다.
- `null`, 배열처럼 올바른 요청 객체가 아닌 JSON 입력은 서버 오류 대신 잘못된 요청으로 처리합니다.
- 이전 대화 맥락에 숨긴 프롬프트 인젝션과 위기 관련 표현도 새 질문과 같은 기준으로 검사합니다.
- 쿠키 암호화 비밀값이 잘못 설정된 경우 오류를 숨긴 채 세션을 계속 만들지 않습니다.
- AI 답변 평가는 대화 원문이나 IP 주소를 저장하지 않는 기존 원칙을 유지합니다. 피드백 날짜는 UTC 기준으로 통일하고 180일 보존 정책을 유지합니다.

## 어떤 기록이 영향을 받나요?

다음 조건에 해당하지 않는 기존 구조요약 결과는 다시 계산할 필요가 없습니다.

1. 한 반응의 [Contents]에 같은 부호를 두 번 이상 입력한 기록
2. 데스크톱과 모바일에서 Level 1·Level 2 특수점수 정리 결과가 다르게 저장된 기록
3. 허용되지 않은 Z 부호나 카드에 맞지 않는 Z 점수가 외부 자료 또는 오래된 저장본에 남은 기록
4. 모바일 화면에서 `C`, `C'`, `T`, `V`, `Y`, `Cn`처럼 형태를 사용하지 않는 결정인만 입력했는데 [FQ]가 `none`이 아닌 값으로 저장된 기록

해당 기록은 원자료를 확인해 중복 또는 잘못된 부호를 바로잡은 뒤 다시 계산합니다. 앱은 임상가의 부호화 판단을 대신하지 않습니다.

## 테스트 및 검증

- S-CON은 정확히 8개 기준을 충족할 때 `Positive`, 7개일 때 `NO`가 되는 경계 사례를 고정 검사로 추가했습니다.
- OBS는 실제 최종규칙이 충족되는 사례를 별도로 만들어 판정값을 확인했습니다.
- 같은 내용 부호의 중복, Level 1·Level 2 충돌, 빈 특수점수, 잘못된 Z 부호, 손상된 자동저장 자료, 브라우저 저장소 접근이 차단된 환경, 잘못된 BYOK JSON 본문을 각각 재현했습니다.
- 전체 자동 검사에서 95개 테스트 파일의 587개 검사가 통과했고, 실행 조건이 없는 7개는 건너뛰었습니다.
- 다섯 언어 참조 문서 203개씩이 모두 검색 가능한 상태인지 확인했습니다.
- OpenAI 임베딩 5,604개를 새 본문과 대조했으며, 오래된 임베딩은 0개, 본문 해시 불일치도 0개였습니다.
- GPT-5.5 단일 대화 62개, 여러 차례 이어지는 대화 9개, 실제 웹앱 API 경로 4개를 호출해 코딩·해석 경계와 응답 완료 여부를 확인했습니다. 첫 검사에서는 나이 정보가 없는 S-CON 질문 1개가 답변 경계 검사를 통과하지 못했습니다. 경계를 보완한 뒤 해당 질문을 포함한 한국어 관련 질문 2개를 다시 호출해 모두 통과했습니다.
- OpenAI Codex와 Claude Opus 5가 유료 GPT-5.5 호출을 각각 독립적으로 실행했습니다. Claude 감사 환경은 다섯 언어 25개 시나리오를 검사한 뒤, 한 차례 계약 검사를 통과하지 못한 일본어 특수점수 수준쌍 항목을 3회 더 호출했습니다. 추가 3회는 모두 통과해 전체 28회 중 27회 통과, 1회 불통과였습니다. Codex는 질문 문구를 되짚어 올바르게 금지하는 일본어 답변이 통과하는 회귀 검사를 추가하고 같은 항목을 11회 더 호출했으며, 11회 모두 통과했습니다. Codex의 추가 실행은 로컬 도구 제한 시간이 끝나 11회에서 종료되었지만, 완료된 11개 응답 자체에는 중단이 없었습니다.
- 한 차례의 불통과는 계산식이나 입력 규칙의 오류로 재현되지 않았습니다. 해당 응답 원문을 보존하지 않았으므로 특정 오탐 원인도 단정하지 않았습니다. Claude 호출 비용은 `$0.874310`, Codex 후속 호출 비용은 `$0.351305`였습니다. API 키와 답변 원문은 공개 기록에 포함하지 않았습니다.
- 피드백 DB의 4개 마이그레이션과 RAG DB의 30개 마이그레이션을 각각 빈 pgvector 데이터베이스에서 처음부터 재생했습니다.
- 프로덕션 빌드에서 222개 페이지를 생성한 뒤 데스크톱과 모바일 계산기 화면을 직접 열어 보았으며, 브라우저 콘솔 오류는 없었습니다.

AI 호출 검사는 실제 답변의 대표 경계를 확인하는 표본 검사입니다. 모든 임상 질문에 대한 정확성을 보증하지 않으며, 최종 해석과 적용 연령 판단은 임상가가 맡습니다.

## UI/UX, 개인정보와 계산 범위

- 새 화면이나 나이 입력란을 추가하지 않았습니다.
- [Contents]에서 이미 고른 부호가 다른 칸에서 비활성화되고, 잘못된 저장 자료에는 다섯 언어 안내가 표시됩니다.
- 구조요약 결과의 선택되지 않은 탭에도 옅은 테두리를 넣어 현재 탭과 구분하기 쉽게 했습니다. S-CON, DEPI, CDI, HVI 카드에서는 요약 체크박스와 첫 줄 문장을 수직 중앙에 맞췄습니다.
- 계산 공식과 구조요약 결과 화면의 항목은 변경하지 않았습니다.
- 채점 자료와 OpenAI API 키를 서버 데이터베이스에 저장하지 않습니다.
- 피드백 DB에는 정해진 이유 코드와 집계용 정보만 저장하며 대화 원문과 원본 IP 주소는 저장하지 않습니다.

## 남겨 둔 판단

이번 패치에서는 근거가 충분히 확정된 항목만 수정했습니다. Level 1·Level 2로 나뉘지 않는 동일 특수점수를 한 반응에 반복 입력하는 경우에는 동작을 바꾸지 않았습니다. 무형태 결정인의 FQ에 관한 새 임상 기준도 확정하지 않았으며, 기존 데스크톱 정리 동작을 모바일에 동일하게 적용해 화면 간 차이만 없앴습니다. 추가 근거 또는 제품 결정이 필요한 항목은 별도 근거가 확보될 때 다시 검토합니다.

## 공개 범위와 보안 경계

공개 소스에는 입력 검사, 자동저장 복구, S-CON·OBS 경계 검사, 다섯 언어 참조 문서, AI 답변 검사 도구와 재현 가능한 결과를 포함합니다.

공개 미러 정리 스크립트의 `DryRun`은 실제 파일을 삭제하지 않고 예정된 정리 작업만 보여 줍니다.

운영 환경변수, API 키, 실제 사용자의 채점 자료와 대화, 원본 IP 주소, 비공개 원전, 로컬 경로와 내부 작업 기록은 공개하지 않습니다.
