# [2026-07-31] v2.2.8 バグ修正

[한국어](./README.md) | [English](./README.en.md) | [日本語](./README.ja.md) | [Español](./README.es.md) | [Português (Brasil)](./README.pt-BR.md)

## 主な修正内容

### 概要

一つの反応の[Contents]に同じ内容コードを二度入力すると、そのコードが二重に集計される問題を修正しました。たとえば`Bt`を二つの欄に重複して入力すると、Isolation Indexの分子が実際より大きくなり、境界にある記録ではCDIの判定まで変わる可能性がありました。選択済みの内容コードは、同じ反応の別の欄では再度選択できません。過去の自動保存データに重複が残っている場合、元のデータを勝手に書き換えずに計算を停止し、確認が必要な行を知らせます。

デスクトップ表とモバイルカードで別々に管理していた反応整理規則も共通化しました。`DV`、`DR`、`INCOM`、`FABCOM`系列でLevel 1とLevel 2が同時に存在する場合は、画面で直前に選択したコードを残し、それまでの競合コードを削除します。過去の保存データに両方のレベルがすでに含まれている場合は、従来のデスクトップ動作を維持してLevel 1を残します。どちらのレベルが正しいかは、臨床家が原資料に基づいて確認する必要があります。削除された欄に空のSpecial Scoreは保存せず、同じ入力は両画面で同じ整理結果になります。

このリリースは構造一覧表の計算式を変更しません。規則どおり入力された既存プロトコルを再計算する必要はありません。下の「どの記録が影響を受けますか？」に記載した条件に該当する記録だけを原資料で確認し、修正後に再計算します。

### 自動保存と入力データ

- 保存済みの作業がある状態でサンプルデータを開いても、既存の自動保存を上書きしません。
- 編集直後に画面を閉じたり別ページへ移動したりしても、最後の変更を保存します。
- 構造が壊れている、または過度に大きい自動保存データは、正しい記録として復元せず安全に拒否します。
- 許可されていないZコードと、選択したカードに属さないZ得点は計算前に遮断します。
- CSVファイル名には使用中の端末のローカル日付を用います。書き出し時には、表計算ソフトが数式として実行し得る文字列だけを安全に処理し、臨床上有効な正負の値と単独の採点記号は元の値を保ちます。コンマ、引用符、CR・LF改行を含むセルもCSV規則に従って引用します。

### S-CONと参照文書

五言語のS-CON参照文書に、12の基準と`8項目以上`という判定境界をすべて記載しました。計算機は従来どおり12基準の該当数を数え、8項目以上でチェックし、15歳以上の受検者に適用するという注意を併記します。年齢入力欄は追加せず、年齢条件を適用する判断は臨床家に委ねます。

年齢が提示されていないS-CONの質問では、AI解釈支援がまず該当基準数を説明し、正確な年齢を尋ねます。年齢が不明なままS-CONを陽性または陰性と確定したり、報告書にそのまま使える文を作成したりしないよう回答規則を強化しました。

### AIセッションとフィードバックの安全性

- APIキーのセッション発行とチャット要求に、Cookieの切り替えだけでは回避しにくい要求制限を追加しました。
- `null`、配列など正しいオブジェクトではないJSON本文は、サーバーエラーではなく不正な要求として処理します。
- 引き継いだ会話文脈にも、プロンプトインジェクションと危機表現の検査を適用します。
- Cookie暗号化用の秘密値が誤って設定されている場合、エラーを隠してセッションを作り続けません。
- AI回答評価では会話本文と生のIPアドレスを保存しない従来の原則を維持します。日時はUTCに統一し、180日間の保存方針を維持します。

## どの記録が影響を受けますか？

次の条件に当てはまらない既存の構造一覧表結果は、再計算する必要がありません。

1. 一つの反応の[Contents]に同じコードを二回以上入力した記録
2. デスクトップとモバイルでLevel 1・Level 2のSpecial Scoreの整理結果が異なって保存された記録
3. 未対応のZコード、またはカードに属さないZ得点が外部データや過去の自動保存に残っている記録
4. モバイル画面で`C`、`C'`、`T`、`V`、`Y`、`Cn`などの無形態決定因だけを入力したにもかかわらず、[FQ]が`none`以外の値として保存された記録

該当する記録は原資料を確認し、重複または不正なコードを修正してから再計算します。アプリは臨床家のコーディング判断に代わるものではありません。

## テストと検証

- S-CONは基準が正確に8項目なら`Positive`、7項目なら`NO`になる境界事例を固定テストに追加しました。
- OBSは実際の最終規則が成立する事例を別に作り、判定値を確認しました。
- 内容コードの重複、Level 1・Level 2の競合、空のSpecial Score、不正なZコード、壊れた自動保存、ブラウザ保存領域へのアクセスが遮断された環境、不正なBYOK JSON本文を個別に再現しました。
- 全自動テストでは95テストファイルの587件が通過し、実行条件のない7件はスキップしました。
- 五言語それぞれ203件の参照文書がすべて検索可能な状態であることを確認しました。
- OpenAI埋め込み5,604件を現行本文と照合し、古い埋め込みは0件、本文ハッシュ不一致も0件でした。
- GPT-5.5の単一ターン62件、複数ターン9件、実際のウェブアプリAPI経路4件を呼び出し、コーディング・解釈の境界と回答完了を確認しました。初回では、年齢情報がないS-CONの質問1件が回答境界の検査を通過しませんでした。境界を補強した後、この質問を含む関連する韓国語の質問2件を再実行し、いずれも通過しました。
- OpenAI CodexとClaude Opus 5が、それぞれ独立して有料のGPT-5.5呼び出しを実行しました。Claudeの監査環境は五言語25シナリオを検査し、契約検査を一度通過しなかった日本語のSpecial Scoreレベル対項目をさらに3回呼び出しました。追加の3回はすべて通過し、全28回中27回通過、1回不通過でした。Codexは、質問文を繰り返しながら正しく禁止を示す日本語回答が通過する回帰テストを追加し、同じ項目をさらに11回呼び出しました。11回はすべて通過しました。Codexの追加実行はローカルツールの制限時間に達したため11回で終了しましたが、完了した11件の応答自体に中断はありませんでした。
- 一度の不通過は、計算式または入力規則の誤りとして再現されませんでした。該当応答の本文を保存していないため、特定の偽陽性原因も断定していません。Claude呼び出しの費用は`$0.874310`、Codexの追加呼び出しの費用は`$0.351305`でした。APIキーと応答本文は公開記録に含めていません。
- フィードバックDBの4マイグレーションとRAG DBの30マイグレーションを、それぞれ空のpgvectorデータベースで最初から再生しました。
- 本番用ビルドで222ページを生成し、デスクトップとモバイルの計算機画面を直接開きました。ブラウザコンソールのエラーはありませんでした。

AIの実呼び出しは代表的な回答境界を確認する標本検査です。すべての臨床質問に対する正確性を保証するものではありません。最終解釈と適用年齢の判断は臨床家が行います。

## UI/UX、個人情報、計算範囲

- 新しい画面や年齢入力欄は追加していません。
- [Contents]で選択済みのコードは別の欄で無効になり、不正な保存データには五言語で案内を表示します。
- 構造一覧表の結果画面では、未選択のタブにも薄い境界線を付け、現在のタブと区別しやすくしました。S-CON、DEPI、CDI、HVIの各カードでは、要約チェックボックスと最初の文を垂直方向の中央に揃えました。
- 計算式と構造一覧表結果画面の項目は変更していません。
- 採点データとOpenAI APIキーはサーバーDBに保存しません。
- フィードバックDBには定められた理由コードと集計用情報だけを保存し、会話本文と生のIPアドレスは保存しません。

## 今回変更しなかった判断

このリリースでは、根拠を十分に確認できた項目だけを修正しました。Level 1・Level 2の区分がない同じSpecial Scoreを一つの反応に重複入力した場合の動作は変更していません。無形態決定因へのFQ付与について新しい臨床規則を確定したわけではなく、従来のデスクトップの整理動作をモバイルにも適用して、両画面の差だけをなくしました。追加の根拠または製品上の決定が必要な項目は、十分な根拠が得られた時点で再検討します。

## 公開範囲とセキュリティ境界

公開ソースには、入力検査、自動保存の復旧、S-CON・OBS境界検査、五言語の参照文書、AI回答評価ツール、再現可能な結果を含めます。

公開ミラーの整理スクリプトでは`DryRun`が実際のファイルを削除せず、予定される整理処理だけを表示します。

運用環境変数、APIキー、実際の利用者の採点データと会話、生のIPアドレス、非公開原資料、ローカルパス、内部作業記録は公開しません。
